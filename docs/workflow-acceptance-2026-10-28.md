# يمن درايف — استكمال دورة الرحلة والموافقات

التاريخ: 2026-10-28

## حالة التسليم

اكتمل التنفيذ البرمجي والتحقق الآلي للبنود الثمانية، مع بقاء القبول على هاتفين فعليين ونشر نسخة الخادم والتطبيقين معًا. اجتازت مجموعة الراكب 129 اختبارًا ومجموعة السائق 64 اختبارًا؛ وأُعيدت اختبارات قبول السائق الستة بعد آخر حماية من نتائج الطلبات المتأخرة. اختبارات API نجحت على LocalDB مؤقتة معزولة. بُنيت APK Release للتطبيقين بمعماريات armeabi-v7a وarm64-v8a وx86_64، وبناء API ناجح. لا تغييرات نموذج غير مغطاة بترحيل.

هذه نتائج تحقق جديدة في 28 أكتوبر، وليست إعادة نقل لنتائج الدفعة السابقة. لم تُشغّل هذه التعديلات على قاعدة المستخدم ولم يُعد تشغيل الخادم المنشور. لذلك لا يُعد القبول الميداني مكتملًا بعد.

## العقود والحالات

- `RideModel/update`: السائق يؤكد `status=9` بعد التعيين/التوجه، ثم يبدأ بـ`status=5`، وينهي بـ`status=6`. وصول السائق لا يضع StartedAtUtc.
- `RideCancellationRequestModel/add`: يقبل راكب الرحلة أو سائقها وفق الحالة؛ `accept/reject` يتحققان من الطرف صاحب القرار. تظهر الواجهة الأزرار بناءً على `requestedByDriver` و`canDecide`.
- `RideRouteChangeModel`: `quote/add/cancel` للراكب؛ `accept/reject` للسائق المسند، مع إعادة فحص الفاتورة والمدة والموقع قبل التطبيق.
- `RideSearchRecipientModel/get`: `{ rideId }` للراكب صاحب الرحلة أو الإدارة؛ يعيد السائق ووقت إرسال الدعوة ووقت مشاهدتها إن وجد.
- `RideRequestAvailabilityModel/get`: `{ rideId }` يعيد `available` بعد فحص الدعوة وحالة الرحلة والسائق والاتصال والقرب والخدمة.
- `PendingRideRatingModel/get`: أقدم رحلة مكتملة دون تقييم أو `null`؛ خطأ `rating_required` يمنع إنشاء/إعادة بحث رحلة قبل التقييم.
- إشعارات تغيير المسار تتضمن `routeChangeId`؛ طلب الانتظار يتضمن `action=review_waiting`. أحداث الحالة تصل إلى مجموعات الرحلة والراكب والسائق.
- حداثة وجود السائق تستند إلى حالة الاتصال وآخر موقع محفوظ، وFCM يمنع تخزين دعوات الرحلات غير القابلة للتسليم الفوري. إعادة الاتصال تجلب الطلبات الصالحة فقط.
- مجموعة Postman الحالية محدثة بتأكيد الوصول وأمثلة العقود الجديدة. الموافقة والرفض بدائل؛ لا تشغلهما متتاليين كاختبار رحلة واحدة.

## ما بقي للقبول الميداني

1. نشر الخادم والتطبيقين معًا في بيئة الاختبار؛ النسخ القديمة لا تعرف حالة الوصول 9 والعقود الجديدة. لم يُحدّث الخادم المشغّل ضمن هذه الدفعة.
2. رحلة كاملة على هاتفين: تغيير الوجهة بقبول ورفض، إلغاء قبل البدء وأثناءه، استعادة توفر السائق، الوصول ثم البدء، ثم الإنهاء والتقييم وإعادة التشغيل.
3. اختبار FCM على أجهزة فعلية في الواجهة والخلفية وبعد إغلاق التطبيق، مع فصل الشبكة حتى انتهاء الطلب أو قبوله بواسطة سائق آخر. لم يُرسل إشعار فعلي أو دفع فعلي في هذه الدفعة.
4. سماع صوت العروض والتحقق من عدم تكراره، وفحص GPS والخلفية وعودة التطبيق؛ اختبارات الوحدات لا تثبت توصيل Android أو الأداء الميداني.
