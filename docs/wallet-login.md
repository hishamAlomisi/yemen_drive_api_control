# تسجيل دخول محافظ الدفع

أُضيفت مكتبات `eqsWallets` بإصدار `0.10.0` من مجلد `net8.0` إلى مشروع API. يدعم كتالوج تسجيل الدخول: جيب `Jaib`، جوالي `Jawali`، فلوسك `Floosak`، كاش `Cash`، سبيد `Speed`، موبايل موني `MobileMoney`، وياه موني `YeahMoney`.

من لوحة التحكم افتح **طرق الدفع الخارجية**، ثم أضف طريقة أو عدّل طريقة موجودة. اختر نوع **محفظة خارجية** والمزود من القائمة؛ يظهر قالب JSON بحقول تسجيل الدخول المحددة للمحفظة فقط. أكمل بياناتك ثم فعّل **تسجيل الدخول تلقائياً** واحفظ. عند التعديل يُحمّل حقل JSON بيانات الدخول المحفوظة لتعديلها مباشرة. تبقى البيانات مشفّرة في قاعدة البيانات، وتُعرض فقط داخل نموذج التعديل للمسؤول وتُمسح من الحقل عند إغلاقه أو انتهاء الجلسة؛ لا تُخزّن في تخزين المتصفح. إذا تعذّر تحميلها يظهر السبب دون تعبئة قالب بديل تلقائياً. ترك JSON فارغاً يحافظ على البيانات المخزنة، وحفظه دون تغيير لا يبدأ محاولة دخول جديدة. زر تعبئة القالب يساعد على استبدال الإعدادات كاملة. تغيير المزود يحتاج بيانات ذلك المزود لتفعيل تسجيل الدخول.

الخادم يتحقق من JSON ومن نموذج المكتبة قبل الحفظ. عنوان `BaseAddress` يجب أن يكون HTTPS صالحاً. `CertificatePath` في إعدادات جيب هو مسار الشهادة على جهاز الخادم؛ لا يُرسل ملف الشهادة من لوحة التحكم.

داخل نص JSON، اكتب مسار شهادة ويندوز بشرطتين خلفيتين لكل فاصل:

```json
{
  "CertificatePath": "D:\\path\\sss.pfx"
}
```

ويمكن استخدام الشرطة الأمامية: `"CertificatePath": "D:/path/sss.pfx"`. أما `"D:\path\sss.pfx"` فليست صيغة JSON صالحة؛ الشرطة الخلفية المفردة تبدأ محرفاً مهرباً، وقد تتحول بعض المقاطع مثل `\t` إلى محرف جدولة. بعد قراءة JSON يصبح المسار الفعلي `D:\path\sss.pfx`. يجب أن يكون الملف موجوداً على الخادم ويمكن لحساب تشغيل API قراءته. مكتبة جيب تفتح ملف الشهادة بكلمة المرور الناتجة عن وصل `ProviderGrant` ثم `AgentClientSecret` دون فاصل؛ لا يوجد حقل `CertificatePassword` في خيارات جيب.

على ويندوز تُحمّل شهادة جيب افتراضياً بمفاتيح حساب تشغيل API الحالي (`UserKeySet`)، لتجنب فشل الاستيراد بسبب عدم امتلاك الحساب صلاحية مخزن مفاتيح الجهاز. لا تحتاج إضافة حقل جديد إلى قالب جيب ذي الحقول الـ12. إذا أُدخل `CertificateKeyStorageFlags` صراحةً في JSON، يُحترم الخيار المحدد بدلاً من هذا الافتراضي.

قالب فلوسك يحتوي `BaseAddress` و`Environment` و`PhoneNumber` و`Password` و`CashInRoute`. يمكن إضافة `SourceWallets` و`TopUpProducts` عند الحاجة؛ لا يظهران في القالب الافتراضي. خرائط العملات تستخدم رموزاً مثل `YER` و`SAR` كمفاتيح. مثال هذين الخيارين:

```json
{
  "SourceWallets": { "YER": 12345 },
  "TopUpProducts": { "product-reference": { "Method": 1, "Bunch": 2 } }
}
```

هذا مثال لجزء من الإعدادات فقط؛ استعمل قالب المزود الكامل لإدخال بيانات الدخول.

يحفظ جدول `PaymentProviderAccounts` حساباً واحداً لكل سجل `PaymentMethod`. يحفظ JSON داخل `CredentialsEncrypted`، مع تفعيل الدخول وإصدار الإعدادات وحالة آخر محاولة. بيانات الجلسة تبقى داخل نسخة `WalletClient` مستقلة لكل سجل في ذاكرة عملية API؛ المكتبة لا توفر تصديراً عاماً لتوكن الجلسة.

عند تشغيل API تبدأ محاولة واحدة لكل حساب مفعّل وطريقة دفع نشطة. تُفحص تغييرات الإعدادات كل خمس ثوانٍ؛ تغيير بيانات الدخول أو إعادة تفعيل الحساب أو طلب إعادة المحاولة يبدأ محاولة جديدة. لا يُعاد تسجيل الدخول بصورة دورية للحساب نفسه بعد النجاح أو الفشل. تتولى المكتبة صلاحية جلساتها وتجديدها داخل عملياتها المدعومة. تعطيل الحساب أو الطريقة أو حذفها يزيل العميل من الذاكرة في الفحص التالي؛ لا تُقبل نتيجة محاولة قديمة إذا تغيّر إصدار الإعدادات أثناء الاتصال.

تعرض اللوحة الحالات: لم تُضبط البيانات، بانتظار الدخول، جارٍ الدخول، متصلة، فشل الدخول، ومعطلة. زر إعادة المحاولة يطلب محاولة جديدة في الخلفية. تُعاد أكواد أخطاء عامة في الحالة؛ لا يتضمن مسار الحالة كلمات المرور أو نص استجابات المزود.

تتابع صفحة طرق الدفع حالة تسجيل دخول المحافظ كل ثلاث ثوانٍ أثناء عرضها، وتحدّث خلية الحالة فقط عندما يتغير محتواها. تتوقف المتابعة عند مغادرة الصفحة أو إخفاء التبويب أو تسجيل الخروج، وتُستأنف عند العودة. هذه الطلبات تقرأ الحالة المعروفة لدى API ولا تبدأ محاولات دخول جديدة ولا تقرأ بيانات JSON السرية. عند تعذر الاستعلام تظهر «تعذر تحميل الحالة» وتستمر المحاولة تلقائياً عند عودة الاتصال.

مسارات الإدارة المحمية:

- `GET /api/admin/wallet-providers`: أسماء المحافظ وقوالب الإعدادات الخالية من بيانات المستخدم.
- `GET /api/admin/payment-methods/{id}/wallet-login`: حالة الحساب دون بيانات الدخول.
- `GET /api/admin/payment-methods/{id}/wallet-login/configuration`: بيانات JSON المحفوظة مفكوكة التشفير للمسؤول النشط عند فتح التعديل فقط، مع `Cache-Control: no-store`. يعيد `providerOptionsJson: null` عند غياب البيانات، وخطأً واضحاً إذا تعذّر فكّها.
- `POST /api/admin/payment-methods/{id}/wallet-login/retry`: جدولة محاولة جديدة لحساب مفعّل.
- `PaymentMethodModel/add` و`update`: الحقلان الاختياريان `ProviderOptionsJson` و`ProviderLoginEnabled`.

يستخدم التشفير ASP.NET Data Protection مع مفتاح دائم في `security/wallet-keys` تحت مجلد التطبيق. يمكن تحديد مكان دائم بديل عبر `WalletLogin:KeyRingPath`. احتفظ بالمجلد ومفاتيحه عند تحديث النسخة وخذ نسخة احتياطية منه مع قاعدة البيانات؛ فقدانه يمنع فك البيانات المخزنة. على Windows تُحمى المفاتيح بواسطة DPAPI لحساب تشغيل API، لذا يتطلب نقل الخادم أو تغيير حساب الخدمة إعادة إدخال البيانات أو إدارة المفاتيح بالطريقة المناسبة للبيئة الجديدة. على الأنظمة الأخرى يجب حماية مجلد المفاتيح بصلاحيات نظام الملفات.

الترحيل `20261029164336_PaymentProviderAccounts` يضيف الجدول فقط، ويطبّق مع الترحيلات الحالية عند تشغيل API المهيأ. لم تتغير عمليات الدفع الفعلية؛ هذا الإصدار يجهز تسجيل الدخول فقط.

التحقق:

```powershell
dotnet run --project tests/YemenDrive.WalletLoginTests --no-launch-profile
dotnet run --project tests/YemenDrive.FinancialIntegrationTests --no-launch-profile
```

تستخدم الاختبارات قواعد LocalDB مؤقتة وعملاء دخول وهميين؛ لا تتصل بمحافظ حقيقية. يلزم إدخال بيانات صحيحة من اللوحة للتحقق من تسجيل الدخول لدى المزود الفعلي.
