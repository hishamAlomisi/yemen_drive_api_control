# تنفيذ التزامن المباشر والتتبع — سجل النتائج

التاريخ: 3 نوفمبر 2026 بتوقيت الرياض. المرجع: [الخطة المعتمدة](realtime-and-adaptive-tracking-upgrade-plan-2026-11-03.md) و[تغطية الأحداث والعقود](realtime-event-coverage-2026-11-03.md).

**الحالة: تنفيذ واختبار وحزم جاهزة؛ ليس اعتماد إطلاق إنتاجي.** تعدلت المكونات الأربعة وقاعدة البيانات. الخيارات الجديدة غير مفعلة في التشغيل. لم تُنشر الحزمة أو تُطبّق على قاعدة الإنتاج، ولم يُنشأ commit ضمن هذا العمل. بعد انتهاء الاختبار وبطلب صاحب المشروع، جُهزت نسخة API لويندوز وستة ملفات APK مقسمة على الدومين الجديد في مجلد إخراج مستقل. بقيت التعديلات السابقة والمتزامنة غير المرتبطة محفوظة.

## ما تغير

- **سجل الحالة:** حفظ التغيير وإشارة الحدث في المعاملة نفسها، ونسخ متزايدة لكل مورد، وهوية حدث ثابتة وoperationId مشترك للمعاملة. توزيع مستقل بحجز وإعادة محاولة وإيقاظ بعد الاعتماد. تنظيف التاريخ المنشور مستقل ويحفظ أحدث حالة لكل جمهور والأحداث المعلقة.
- **الاستعادة:** صفحات مصرح بها تتجاوز 512 نطاقاً مع ذاكرة نسخ محدودة. لا تقر الواجهة النسخة قبل نجاح قراءاتها المعتمدة، ولا تطبق رداً متأخراً بعد تبديل الحساب أو الاتصال أو المورد.
- **التطبيقان:** ربط الرحلة والدفع والمحفظة والمحادثة والإشعارات ولوحات المتابعة. منع حمولة محادثة قديمة من تجاوز الحالة المعتمدة. إصلاح مثبت لإلغاء قراءة المحفظة وتكرارها بسبب أحداث غير مرتبطة؛ أصبحت مراجعة صلاحية الرد مرتبطة بموارده.
- **السائق:** مخزن SQLite للنقاط غير المقرة، بهويات عينات وجلسات وتسلسل ثابت، ودفعات بحد أقصى 64 عينة وسعة 20,000 عينة للحساب. علامة نقص التسجيل تمنع الادعاء الصامت باكتمال المسار عند امتلائه. أوامر المسار تنتظر الإقرار، بما فيها إلغاء رحلة بدأت.
- **GPS:** إيصالات العينات وأرشيف الحساب في معاملة واحدة. قفل SQL مشترك بين الدفعات والبديل القديم يمنع ازدواج النقطة. العينات التاريخية لا تصبح موقعاً حياً. فحص فجوات التسلسل ووجود مرساة القياس في الأرشيف.
- **التتبع والعرض:** متابعة مصرح بها لمدة 90 ثانية وتجديد 45 ثانية. سياسة إرسال السائق اختيارية: 1 ثانية لرحلة يشاهدها مستخدم، 3 ثوانٍ لرحلة دون مشاهد، 3/15 ثانية لمتاح متحرك/ثابت، وإلا 30 ثانية. طابور مرئي محدود بأحدث عينة منتظرة للسائق، يعيد فحص حالته والرحلة عند التسليم.
- **الإدارة:** رفض GPS القديم والمكرر والقافز، وحماية لقطات الحالة ودورة حياة متابعة الخريطة، وتحديث العلامة والعمر دون إعادة بناء قائمة الرحلات لكل نقطة.
- **Push:** صرف اختياري متواصل للدفعات بما يصل إلى أربعة إرسالات متزامنة لكل عامل وسياقات مستقلة، مع بقاء قواعد الصلاحية والحجز والتحقق من الجلسة وإعادة المحاولة. التراجع لا يوقظ العامل.

**لم تُحذف مؤقتات استطلاع الأعمال.** مصفوفة التغطية تسجل ما بقي وسبب بقائه. لم يتغير تسعير العمل أو قواعد النقد والاسترداد لغرض تحسين النقل.

هذه نتيجة ناجحة لفحوص صحة الأوامر والإيصالات والأرشيف والاستعادة التي ينفذها المولد. **ليست صفراً من الأخطاء في جميع المسارات:** فشل 37 إرسالاً مرئياً، وأعلى الأزمنة يتجاوز الأهداف حتى عندما يحقق المئين هدفه. يشمل فرق عدد GPS الاختصار وفشل العرض وفترة الانقطاع المقصودة؛ processed ليس إقراراً من الجهاز. لا تخفي المئينات هذا الفارق، ولا تثبت السلاسة على هاتف.

سبقت التشغيل تجربتان تشخيصيتان مدة كل منهما 30 ثانية: 25 زوجاً في المزيج القديم (75 تغييراً و25 إعادة اتصال وصفر أخطاء)، ثم 5 أزواج في الدفعات (80 عينة تطابقت مع الإيصالات والأرشيف وصفر أخطاء). الأدلة realtime-v4-mixed-diagnostic.json وrealtime-v4-durable-mixed-diagnostic.json. تداخل بعض الاختبارات والبرامج الأخرى مع بيئة القياس؛ لا تنسب إخفاقات العرض إلى سبب بعينه دون عزل إضافي.


**تشخيص الفشل المختلط:** سجل SQL system_health أظهر 285 حالة deadlock داخل قاعدة الاختبار؛ الاستعلام عن جمهور الرحلات بصيغة Id IN OPENJSON تحت SERIALIZABLE كان يقرأ صفوف رحلات تقفلها معاملات أخرى. الدليل benchmark-v3-deadlock-input.log. استُبدل بقراءات مفتاحية محددة، ونقل تجميع جمهور الأحداث السابقة إلى القفل الخاص بالنطاق، وأضيف فهرس للعروض. نجح اختبار 25 كاتباً متزامناً دون تغيير عزل معاملات الأعمال أو مهلها؛ انتهى الحمل المختلط اللاحق لمدة نصف ساعة دون أخطاء SQL أو أوامر، مع تسجيل إخفاقات العرض المرئي منفصلة أدناه.

توقف المرجع realtime-v3-baseline-L1-30m قبل نهايته عند 1590 ثانية بعد اختفاء عمليتي الاختبار؛ آخر نقطة 87045/87045 عينة وصفر أخطاء. لا توجد نتيجة نهائية، لذلك لا يحتسب نصف ساعة ناجحة. اكتمل التشغيل المحدث realtime-v4-upgraded-L1-durable-30m كما في الجدول أعلاه. completed=true يعني انتهاء التشغيل فقط، وحتى exit 0 لا يفحص تلقائياً عدادي إخفاق العرض وSQL. القرار يعتمد على قراءتهما مع أخطاء العمليات، وأحدث المواقع، وتطابق العينات والإيصالات والأرشيف، والفجوات.

الدفعات في مولد الحمل تحتوي نقطة واحدة عبر HTTP وSignalR بالتناوب، وتكرر كل عاشر تسلسل؛ لا تختبر تشبع دفعة 64 نقطة ولا تحقن ضياع رد فعلياً. رموز الوصول الاختبارية صالحة ست ساعات، لذا حركة تجديدها مستبعدة. حمل الإدارة اتصالات بث، ولا يمثل التنقل بين التقارير والدفاتر.

الحمل المختلط يغير اختيار وسيلة الدفع ويجمع إعادة الاتصال قرب المنتصف؛ لا ينفذ تحويل أموال أو تحصيل مزود ولا يمثل موجة قبول/إلغاء كاملة. زمن stateCreatedToClientMs يبدأ بإنشاء السجل قبل الاعتماد، وليس بالاعتماد إلى التطبيق على الهاتف. لا تجوز مقارنة GPS في حمل مختلط بمرجع GPS وحده لإثبات تحسن سببي.

3. **سحب صلاحية اتصال قائم:** المراجعة كشفت بقاء عضوية SignalR بعد تغيير الدور/تعطيل الحساب. أُصلح الإغلاق من جهة الخادم بعد الاعتماد واجتاز 19 تأكيداً مع اتصالات فعلية. يعمل فوراً على نسخة API نفسها؛ اتصال خامل بنسخة أخرى يحتاج إشارة موزعة. قد تبقى واجهة الدخول المخزنة حتى قراءة REST التالية أو استئناف التطبيق، بينما يمنع الخادم الوصول بالفعل.
4. **الأجهزة:** صاحب المشروع أكد عدم توفر هواتف. الخلفية وقتل التطبيق والبطارية ودقة المسار المرجعي وتنعيم العلامة وزمن الهاتف غير متحقق منها.
5. **السعة:** اجتاز المزيج المصحح فحوص المولد لمدة نصف ساعة؛ تبقى المقارنة المكتملة والمستويات الأعلى والاستقرار الطويل والتنظيف وتحليل إخفاقات العرض. لا توجد سعة إنتاج معتمدة بهذه الأدلة.
6. **عدة نسخ API:** الأقفال لا توفر وحدها backplane أو متابعة وسحب جلسات موزعين. الأرشيف الطويل واحتفاظ إيصالات المسار يحتاجان سياسة تشغيل قبل التوسع.

## التفعيل والرجوع

قبل التفعيل: نسخة قاعدة بيانات واختبار استعادتها منفصلاً، ثم الترحيلات الإضافية، واختبار تركيبات القديم والجديد، وتجربة محدودة لكل خيار مع قياس الأخطاء والطوابير والاستعادة. مخزن السائق الدائم لا يصدر شهادة اكتمال مقابل خادم لا يقر العينات.

الرجوع بإيقاف الخيارات أو إعادة الإصدار المتوافق **مع إبقاء الجداول والبيانات المعتمدة**؛ لا تستخدم Down لحذف سجل أو إيصالات حقيقية. قبل إيقاف رفع العينات الدائمة تُصرف النقاط المحلية غير المقرة ويتحقق من إقراراتها؛ إن تعذر ذلك تبقى محفوظة وتتوقف العملية التي تتطلب إثباتها. لا تمسح علامة نقص التسجيل لإظهار نجاح شكلي.

الاختبارات الحالية تثبت توافق الوضع الافتراضي وبقاء المال والتاريخ عند تعطيل السجل. لا تعادل اختبار تركيب وترقية ورجوع كامل على هواتف وتشغيل فعلي.
