تمت متابعة المحادثة «اعادة تصحيح الية الطلب» وتنفيذ القرارات الأربعة عشر المعتمدة على المصدر الحالي. هذا تقرير تنفيذ واختبار محلي؛ لا يمثل اعتماد تشغيل مالي حقيقي. يحل وصف السلوك النهائي هنا محل التقارير السابقة المؤرخة التي كانت تربط انتهاء النقل بالدفع أو الاسترداد.

## السلوك النهائي

انتهاء النقل حقيقة مستقلة عن المقبوض والمتبقي والاسترداد والنزاع. مثلاً، رحلة مستحقها 1000 ومقبوضها 400 يمكن إنهاء نقلها؛ يظهر المتبقي 600 ولا يسجل كقبض. يظهر مستحق السائق غير المحصل مستقلاً عن محفظته القابلة للسحب. الدين المؤكد غير المتنازع عليه يحظر الحجز حتى السداد؛ المبلغ قيد مراجعة تسوية الإلغاء أو النزاع لا يتحول تلقائياً إلى دين نهائي.

النقد الزائد حق للراكب؛ لا يحول إلى المحفظة بلا اختياره. قول السائق إنه أعاد النقد لا يكفي لإثبات الاستلام. زيادة الوجهة المدفوعة تحتاج موافقة ودفع الفرق قبل تطبيقها، ونقصها يثبت استحقاق استرداد. رسوم الخدمة الأصلية لا تتكرر، وتظل الدفعات والقيود الأصلية محفوظة.

## تصحيحات أضيفت عند استئناف هذه المحادثة

- تغلق تسوية المحفظة الخارجية المحاولة المؤكدة. يعالج الترحيل المحاولات القديمة المكتملة التي ظلت مفتوحة، بعد مطابقتها بدفعات مؤكدة؛ لا يستدعي المزود ولا يغير قيمة القبض.
- معاينة الإلغاء تعرض المسافة المثبتة حتى بعد حفظ أجرة الجزء المقطوع؛ غياب دليل المسافة يظهر بوضوح مع بقاء الأجرة التي راجعتها الإدارة.
- تحديث اختبارات التكامل القديمة لتشترط مرجع التحصيل، واختيار وجهة الاسترداد، والمراجعة بعد أول رفض، وتأكيد استلام النقد؛ بقيت فحوص القبض والقيود والاسترداد والتكرار فعالة.
- تصحيح نص تأكيد الاسترداد النقدي ورسالة رفض المحفظة، وإزالة وقت وصول افتراضي عند غياب تقدير حقيقي.

## متطلبات التشغيل والحدود المثبتة

1. اعتماد عدد مقاعد الركاب الفعلي لكل مركبة من الإدارة؛ القيمة القديمة غير المثبتة لا تعامل كسعة معتمدة. اعتماد السائق والمركبة والوثائق وصلاحيات الموظفين مسؤولية الشركة.
2. قيم سياسة الوصول ومهلة الالتقاط والرد غير المعتمدة تبقى فارغة. لا تولد رسوم عدم حضور أو غرامات أو سقوط حقوق بسبب قيمة افتراضية.
3. الربط الحالي لا يثبت استرداداً آلياً إلى مصدر فلوسك/جيب، أو سحباً خارجياً لرصيد التطبيق. البدائل تعتمد على موافقة الراكب وتحويل فعلي ممول وأدلة، لا محاكاة تحويل.
4. سياسة الاحتفاظ ومحو البيانات الشخصية تحتاج أساساً معتمداً؛ التنفيذ يتيح طلب الحذف والتعطيل الآمن ومتابعته ويحفظ الأدلة المالية.
5. يلزم اختبار ميداني للتثبيت والتنبيهات بالخلفية ودقة GPS والمسار والاستعادة، واختبار حسابات محافظ معتمدة بالبيئة المناسبة قبل إعلان التشغيل المالي الحقيقي.

## الحزمة

تصحيح تشغيل أضيف بعد التسليم: النشر الأول كان framework-dependent داخل مجلد يحتوي runtime مستقلاً سابقاً، مما منع تشغيل EXE مباشرة. أعيد النشر كـself-contained win-x64 مع .NET 9.0.18، وأضيف ملف النشر `LocalWindows.pubxml`. اختبر تشغيل EXE وBAT كل على حدة على منفذ 5099 دون نسخ إعدادات قاعدة التشغيل أو بيانات المحافظ؛ أعادت لوحة الإدارة HTTP 200. ملف BAT يبقي النافذة مفتوحة عند خروج البرنامج بخطأ. حدث مجلد التشغيل والحزمة، وبقي المنفذ 5080 متاحاً للتشغيل اليدوي. لا تحتاج هذه النسخة تثبيت .NET في النظام.

توجد ملفات APK الراكب 1.1.8+10 والسائق 1.1.4+7 وملفات API المنشورة وسجلات الاختبار ودليل التشغيل والبصمات في `E:\Driver\work\release-20261102`. يحفظ التحديث إعدادات قاعدة التشغيل ومفاتيح تشفير المحافظ وتسجيلات السلامة الموجودة. تهاجر قاعدة التشغيل عند تشغيل API المعتاد؛ التجهيز اختبر الهجرة على النسخة المعزولة فقط. العودة الآمنة إلى قاعدة قديمة تعتمد على النسخة الاحتياطية المطابقة وملفات تشغيلها، لا إسقاط أعمدة القيود الجديدة.
