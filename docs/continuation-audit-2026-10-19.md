## التحقق

- اختبارات الراكب القائمة: 58 ناجحة قبل إضافة الاختبارات الجديدة. ملف تدفق الحجز بعد الإضافات: 44 اختبارًا ناجحًا، بما فيها خيارات الركوب، ترتيب إعدادات الموقع ثم الصلاحية، البقاء عند عدم التفعيل، تخطي الإلغاء وحفظ السبب، وعرض قبول العرض والمؤقت.
- اختبارا السائق الموجودان ناجحان. تحليل الملفات المعدلة في التطبيقين دون أخطاء أو تحذيرات؛ توجد ملاحظات أسلوبية معلوماتية.
- اختبارات API ناجحة على SQL Server LocalDB جديدة ومعزولة، وتطبق سلسلة migrations كاملة. تشمل بقاء خيارات الركوب في القاعدة ووصولها للسائق، دقيقة العرض، الانتهاء دون شاشة عميل، منع قبول المنتهي، وإعادة إرسال سبب الإلغاء دون تكرار.
- EF أكد عدم وجود تغييرات نموذج بيانات بلا migration. أضيفت `20261019135424_RidePassengerOptions` و`20261019140801_RideOfferExpirationIndex`، والثانية لفهرسة بحث عامل انتهاء العروض بدل مسح السجلات كلها.
- بُنيت حزمة Windows x64 مستقلة. يوجد تحذير Firebase سابق متعلق بـ Message.Token، وتحذير دالة اختبار قديمة غير مستخدمة؛ لا أخطاء بناء.
- صور فحص واجهات الاختبار في `E:/Driver/yemen_drive/build/booking-previews/`: cancellation-reasons، location-access، ride-options، offer-selection. تستبدل الاختبارات الخريطة الأصلية بخلفية؛ لا تثبت تشغيل GPS الحقيقي.
- لم تُنشأ رحلات أو تُنفّذ دفعات أو تُرسل إشعارات تجريبية على قاعدة التشغيل في هذه الدفعة.

## مشاركة الرحلة وGoogle Maps

الرابط الحالي يبث موقع السائق الحقيقي عبر SignalR، وصفحته `shared-ride.js` تستخدم Leaflet وOpenStreetMap. لا تعرض صفحة المشاركة حاليًا طريق الشوارع التفصيلي ولا سجل التحرك. لم تُحوّل إلى Google في هذه الدفعة لأن الطلب السابق كان سؤالًا عن إمكان ذلك.

يمكن عرض التتبع على خريطة Google داخل صفحة المشاركة باستخدام Maps JavaScript API ومفتاح مخصص للمتصفح مقيد بنطاق الصفحة وواجهات Google المطلوبة، مع تهيئة الفوترة. يظل الموقع مصدره SignalR وتبقى صلاحية رابط المشاركة وإلغاؤه في API. فتح تطبيق Google Maps برابط إحداثيات وحده يعرض موقعًا/مسارًا لحظة الفتح، ولا يشترك تلقائيًا في بث التطبيق الحي.

المشاركة خارج الشبكة المحلية تحتاج عنوان HTTPS عامًا يمكن للمستلم الوصول إليه. إعداد عنوان API المحلي وحده لا يوفر مشاركة عبر الإنترنت.

## المتبقي المثبت بالمراجعة، خارج طرق الدفع

1. **تأمين إعداد قاعدة البيانات:** ما زالت مسارات `/api/setup/database/test|save|create` عامة؛ وDatabaseConfigurator يقبل RecreateSchema. يجب تصميم إعداد أولي محلي مؤمن ومنع إعادة إنشاء قاعدة عاملة عبر طلب عام.
2. **توحيد التحقق من صلاحيات الخدمات:** `/api/admin/execute` يفحص المدير، لكن `/api/execute` يمرر إلى الموزع دون بوابة عامة مكافئة؛ يلزم تدقيق مصفوفة كل مودل/عملية، مع إبقاء الدخول وOTP والقراءات العامة المقصودة فقط متاحة دون جلسة. كذلك لا تزال بعض الخدمات تقبل معرف مستخدم يرسله طلب غير مصادق.
3. **إزالة المدير الثابت من التشغيل الإنتاجي:** ما زال تجهيز الحساب الثابت وترقيته موجودين في Program.cs وDatabaseConfigurator.cs. يلزم بديل إعداد أول مدير دون إفساد الحسابات الحالية.
4. **رفع الصور:** مسار `/api/media/upload` يحتاج مصادقة وحدود حجم وتحقق نوع محتوى وصلاحيات ملائمة للرفع. هذه ملاحظات قائمة مثبتة بالمصدر، وليست إصلاحات منفذة في هذه الدفعة.
5. **قبول ميداني:** GPS على هاتفين، الخلفية وإطفاء الشاشة، انقطاع الشبكة وإعادة الاتصال، تغير حالة الرحلة مع السائق ثابتًا، ومشاركة رابط من شبكة خارجية. وجود خدمة أمامية لا يضمن العمل بعد الإيقاف القسري أو قتل النظام للعملية.
6. **الأداء والتوسع:** اختبار الحمل، وفصل حالة SignalR المشتركة عند تشغيل أكثر من نسخة API. لا يوجد في هذه الدفعة إثبات جاهزية التوسع المتعدد.
7. **الإشعارات والسلامة:** المحادثة السابقة تتضمن نجاح FCM على MEmu وإصلاح التسجيل بعد الدخول؛ يبقى اختبار قبول حديث على هاتفين لكل وجهة إشعار ولتسجيل الصوت المتتابع وانقطاع الرفع.
8. **التأخير وتغيير الوجهة:** اقتراح فقط في `delay-and-destination-proposal.md`؛ لم تُضف رسوم انتظار أو آلية تغيير وجهة إلى الرحلة الجارية.

الأولوية التالية المقترحة: تأمين مسارات إعداد القاعدة والتنفيذ العام وحساب المدير والرفع، ثم اختبار قبول الهاتفين؛ بالتوازي يراجع المستخدم سياسة التأخير وتغيير الوجهة المقترحة.

## نتيجة النشر المحلي

أُعيد تشغيل API بعد اعتماد المستخدم، وتأكد بدء الاستماع على http://0.0.0.0:5080 واستجابة admin.html وadmin.js بـ200. سجل بدء التشغيل أثبت تطبيق الترحيلين RidePassengerOptions وRideOfferExpirationIndex على قاعدة التشغيل. حُفظت ملفات security وdata وappsettings دون تغيير، وثُبّت تحديثا التطبيقين على MEmu دون مسح بياناتهما. لا توجد نقطة /health في هذا المشروع؛ التحقق اعتمد بدء التطبيق واستجابة موارده وسجل الترحيل.
### ملاحظة الفحص على MEmu

فتحت نسخة الراكب بعد تحديثها وظهرت الرئيسية والخدمات. ظهرت شوارع الخريطة بخطوط سوداء سميكة، وسجل المحاكي يحتوي EGL_BAD_MATCH. لذلك يبقى فحص رسم الخريطة على هاتف حقيقي ومقارنته بإعدادات الرسومات في MEmu مطلوبًا؛ لم يُنسب السبب نهائيًا إلى الكود أو المحاكي، ولم يُعتبر هذا اختبار GPS ميدانيًا ناجحًا.
