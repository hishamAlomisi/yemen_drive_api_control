# YemenDrive

مشروع ASP.NET Core بسيط يعتمد على Route واحد وخدمات مرتبطة بأسماء المودلات.

## بنية الحل

- `YemenDrive.Api`: نقطة الدخول وصفحة إعداد قاعدة البيانات.
- `YemenDrive.Application`: مودلات ووظائف النظام التي يضيفها المطور.
- `YemenDrive.Services`: الخدمات العامة ودورة التنفيذ الثابتة.
- `YemenDrive.Database`: الجداول وEntity Framework وإعدادات الاتصال.
- `YemenDrive.Shared`: النتائج والعقود والأدوات المشتركة الصغيرة.

## التشغيل

```powershell
dotnet run --project src/YemenDrive.Api
```

لوحة التحكم: `http://localhost:5080/admin`

صفحة الإعداد المنفصلة: `http://localhost:5080/setup`

يمكن فتح الصفحة أيضاً بالضغط على `Ctrl+Shift+D` في نافذة تشغيل التطبيق.

تتعامل لوحة التحكم مع المسار الإداري المحمي `POST /api/admin/execute` بعد تسجيل دخول المدير، بينما يستخدم تطبيق العميل
المسار العام `POST /api/execute`. توفر اللوحة شاشات للإحصاءات والمستخدمين
والسائقين والرحلات والخدمات والتسعير والمحفظة، إضافة إلى محطة لإرسال أي مودل وعملية يدوياً.

## إنشاء قاعدة البيانات واختبارها في Postman

استورد الملف `postman/YemenDrive.postman_collection.json` في Postman، ثم نفذ المجلدات بالترتيب من `01` إلى `06`:

1. `GET /api/setup/database` لعرض الإعداد الحالي.
2. `POST /api/setup/database/create` لإنشاء قاعدة جديدة وتجهيز جميع الجداول.
3. إنشاء مستخدم عميل ومستخدم سائق.
4. إنشاء ملف السائق وموقعه.
5. إنشاء أنواع الخدمات وكتالوج الخدمات وقاعدة التسعير.
6. إنشاء رحلة وعرض سائق ثم اختبار المحفظة.

بعد إنشاء عرض السائق، يقبل العميل العرض قبل تعيين السائق:

```json
{
  "model": "RideOfferModel",
  "operation": "accept",
  "data": { "id": 1 }
}
```

ينقل قبول العرض الرحلة تلقائياً إلى حالة `DriverAssigned` ويثبت السعر المتفق عليه والسائق. بعد ذلك تستخدم
`RideModel/update` مع الحالات `4` لوصول السائق و`5` لبدء الرحلة.

اضبط متغيرات Collection التالية قبل إنشاء القاعدة: `dbServer` و`dbName` و`dbUsername` و`dbPassword`.
لا يحتوي الملف على كلمة مرور محفوظة. تحفظ اختبارات Postman المعرّفات الناتجة تلقائياً لاستخدامها في الطلبات التالية.

بعد إنشاء القاعدة يتم إنشاء حساب المدير التجريبي تلقائياً:

- الهاتف: `700000001`
- كلمة المرور: `Admin1234!`

تسجيل دخول لوحة التحكم يتم عبر `POST /api/admin/login`، وبعد نجاحه تحفظ اللوحة التوكن وتستخدمه تلقائياً مع
`/api/admin/execute`. لا تفتح عمليات اللوحة قبل تسجيل الدخول.

إذا ظهر `404` لمسار الإدارة بعد التعديل، أوقف نسخة API القديمة ثم شغّل المشروع من جديد حتى تُحمّل النسخة الجديدة.

تحتوي قاعدة البيانات على 22 جدولاً مستورداً، منها `Users` و`DriverProfiles` و`Rides` و`RideOffers`
و`Wallets` و`PricingRules` و`RideServiceCatalogItems` و`ServiceKinds`.

استخدم اسماً جديداً وفارغاً للقاعدة عند أول إنشاء. إذا كانت القاعدة موجودة وينقصها بعض الجداول، يعيد API أسماء
الجداول الناقصة بدلاً من إرجاع نجاح غير صحيح.

## طلب إنشاء حساب

يرسل كل عميل الطلب إلى `POST /api/execute`:

```json
{
  "model": "UserModel",
  "operation": "create",
  "data": {
    "displayName": "Test User",
    "email": "user@example.com",
    "phoneNumber": "777000000",
    "password": "Test1234"
  }
}
```

يعثر النظام تلقائياً على الكلاس التالي لأن اسم المودل المرسل هو `UserModel`:

```csharp
public sealed class User : OperationsService<UserModel>
```

الخدمات الثابتة التي يختار المطور واحدة منها:

- `OperationsService<TModel>` للإضافة والتعديل والحذف والقراءة.
- `InitializationService<TModel>` للتهيئة والتجهيز والتحقق.
- `ReportsService<TModel>` للتقارير والقوائم والبحث.

عند إرسال `operation: "add"` أو `operation: "create"` تستدعي خدمة العمليات دالة
`AddAsync` التي عمل لها كلاس `User` عملية `override` تلقائياً.

لإضافة وظيفة جديدة، ضع المودل وكلاس الوظيفة معاً داخل مجلد واضح في `YemenDrive.Application`، ثم اجعل الكلاس
يرث خدمة ثابتة واحدة. يكتشف API الكلاس تلقائياً ولا يحتاج إلى Controller أو Route جديد.

## هوية المستخدم من التوكن

بعد تسجيل الدخول، يرسل العميل التوكن في الهيدر:

```text
Authorization: Bearer <access-token>
```

لا ترسل عمليات المستخدم `customerId` أو `userId` داخل البيانات. يستخرج API هوية الحساب من التوكن ويستخدمها تلقائياً في سجل الرحلات والأماكن المحفوظة والرحلات والمحفظة والدفع وبيانات الحساب.

مثال سجل الرحلات:

```json
{
  "model": "RideHistoryModel",
  "operation": "list",
  "data": {}
}
```

المعرفات التي تبقى في الطلب هي معرفات الموارد، مثل `rideId` أو `savedPlaceId`، وليست معرف المستخدم الذي سجل الدخول.
